# peon-poke Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `bin/peon` — a harness-agnostic shell script that dispatches implementation tasks to external CLI agents (Codex, Grok) in isolated git worktrees — plus a `peon-poke` Claude skill teaching the foreman workflow, restructuring the repo to `skills/plan-check/` + `skills/peon-poke/`.

**Architecture:** Two layers per the approved spec (`docs/superpowers/specs/2026-07-29-peon-poke-design.md`): (1) `bin/peon` encapsulates all provider incantations behind deterministic commands (`dispatch`, `list`, `report`, `diff`, `poke`, `merge`, `scrap`); (2) a prose skill teaches Claude the workflow. Peon output lands on namespaced `peon/<slug>` branches in worktrees under `$PEON_HOME/worktrees/`, never reaching the real tree without orchestrator review and explicit `merge`. A test-only `fake` provider lets the entire lifecycle be tested deterministically without burning provider calls; live provider tests are the final gate.

**Tech Stack:** bash (macOS 3.2-compatible), git worktrees, python3 (JSON read/write only), codex-cli 0.145.0, grok 0.2.112.

## Global Constraints

- **bash 3.2 compatible** (macOS `/bin/bash`): no associative arrays, no `${var,,}`, no `mapfile`. Shebang `#!/usr/bin/env bash`.
- **Runtime deps: git, python3, uuidgen only. Never jq** (missing on some of the user's machines).
- **No hardcoded absolute user paths** — use `$HOME`; all state under `PEON_HOME` (default `$HOME/.peon`), overridable via env for test isolation.
- Worktrees: `$PEON_HOME/worktrees/<repoBasename>-<slug>`; branches: `peon/<slug>`; logs/prompts: `$PEON_HOME/logs/`.
- Providers: `codex`, `grok`, `fake` (fake is test-only, undocumented in `usage`).
- **Never `codex exec resume --last`** — always resume by explicit session id (parallel-safety).
- Codex write mode: `codex exec --json -s workspace-write -c approval_policy=never` (verified: no `--full-auto` on exec in 0.145.0).
- Grok write mode: `--sandbox workspace --permission-mode "$GROK_PERM_MODE"` (default `auto`); pinned new session `-s <uuid>`, resume `--resume <uuid>`. Task 9 live-locks the working permission mode.
- Spec invariants: hub-and-spoke (no peon-to-peon state), draft-until-reviewed, no autonomous merge, one peon per task.
- After every commit in the project repo: `git push` (user works across machines). The `~/.claude` repo has no remote — commit only.
- Test file `tests/peon.test.sh` runs standalone (`bash tests/peon.test.sh`), exits non-zero on any failure.

```bash
slugify() {
  printf '%s' "$1" | tr '[:upper:]' '[:lower:]' \
    | sed -e 's/[^a-z0-9]\{1,\}/-/g' -e 's/^-//' -e 's/-$//' | cut -c1-30 \
    | sed -e 's/-$//'
}

json_str() { python3 -c 'import json,sys; print(json.dumps(sys.argv[1]))' "$1"; }

resolve_repo() {
  git -C "$1" rev-parse --show-toplevel 2>/dev/null || die "not a git repository: $1"
}

require_clean() {
  [ -z "$(git -C "$1" status --porcelain)" ] || die "$2 has uncommitted changes (commit/stash first, or --force to dispatch anyway)"
}

write_meta() {
  local wt="$1"
  cat > "$wt/.peon.json" <<EOF
{
  "slug": "$slug",
  "provider": "$provider",
  "session": "$session",
  "repo": $(json_str "$repo"),
  "base_sha": "$base_sha",
  "branch": "peon/$slug",
  "task": $(json_str "$task"),
  "created": "$(date -u +%Y-%m-%dT%H:%M:%SZ)"
}
EOF
}

update_meta_session() {
  python3 - "$1/.peon.json" "$2" <<'PYEOF'
import json, sys
p, sess = sys.argv[1], sys.argv[2]
m = json.load(open(p))
m["session"] = sess
json.dump(m, open(p, "w"), indent=2)
PYEOF
}

dispatch_prompt() {
  cat <<EOF
You are a "peon": an autonomous implementation agent working in an isolated git worktree on branch peon/$slug. Complete the task below, nothing more.

Rules:
- Commit ALL your changes to the current branch with clear commit messages.
- Never touch or commit .peon.json.
- When done, write PEON_REPORT.md at the repo root covering: what changed, why, how you verified it, open questions. Commit it too.
- Do not push. Do not switch branches. Do not touch files outside this worktree.

Task:
$task
EOF
}

run_fake() {
  local wt="$1" pf="$2"
  SESSION="fake-$slug"
  ( cd "$wt" \
    && cat "$pf" >> "FAKE_WORK-$slug.txt" \
    && git add "FAKE_WORK-$slug.txt" && git commit -qm "fake: do task" \
    && printf '# Peon Report\n\nDid the fake task.\n' > PEON_REPORT.md \
    && git add PEON_REPORT.md && git commit -qm "fake: report" )
}

cmd_dispatch() {
  local provider="" task="" repo="$PWD" base="HEAD" slug="" force=0
  provider="${1:-}"; shift || true
  task="${1:-}"; shift || true
  while [ $# -gt 0 ]; do
    case "$1" in
      --repo) repo="${2:-}"; shift 2 ;;
      --base) base="${2:-}"; shift 2 ;;
      --slug) slug="${2:-}"; shift 2 ;;
      --force) force=1; shift ;;
      *) die "unknown dispatch option: $1" ;;
    esac
  done
  [ -n "$provider" ] || die "usage: peon dispatch <codex|grok> \"<task>\" [--repo DIR] [--base REF] [--slug NAME] [--force]"
  [ -n "$task" ] || die "no task given"
  case "$provider" in
    codex|grok) command -v "$provider" >/dev/null 2>&1 || die "$provider CLI not installed" ;;
    fake) : ;;  # test-only provider
    *) die "unknown provider: $provider (codex|grok)" ;;
  esac
  repo="$(resolve_repo "$repo")"
  [ "$force" -eq 1 ] || require_clean "$repo" "repo $repo"
  local base_sha
  base_sha="$(git -C "$repo" rev-parse --verify "$base^{commit}" 2>/dev/null)" || die "cannot resolve base ref: $base"
  [ -n "$slug" ] || slug="$(slugify "$task")"
  [ -n "$slug" ] || die "could not derive a slug; pass --slug"
  local branch="peon/$slug"
  local wt="$WT_ROOT/$(basename "$repo")-$slug"
  git -C "$repo" show-ref --verify --quiet "refs/heads/$branch" && die "branch $branch already exists (pick another --slug or 'peon scrap $slug')"
  [ -e "$wt" ] && die "worktree already exists: $wt"
  mkdir -p "$WT_ROOT" "$LOG_ROOT"

  # keep .peon.json out of 'git add .' sweeps in every worktree of this repo
  local excl
  excl="$(git -C "$repo" rev-parse --git-path info/exclude)"
  case "$excl" in /*) : ;; *) excl="$repo/$excl" ;; esac
  grep -qx '\.peon\.json' "$excl" 2>/dev/null || echo '.peon.json' >> "$excl"

  git -C "$repo" worktree add -q -b "$branch" "$wt" "$base_sha" || die "git worktree add failed"

  local pf="$LOG_ROOT/$slug.prompt.md"
  dispatch_prompt > "$pf"

  local session=""
  write_meta "$wt"   # metadata lands before the provider runs, so a crashed peon is inspectable

  SESSION=""
  case "$provider" in
    fake)  run_fake "$wt" "$pf" ;;
    codex) die "codex runner not implemented yet" ;;
    grok)  die "grok runner not implemented yet" ;;
  esac
  update_meta_session "$wt" "$SESSION"

  echo "peon dispatched: $slug"
  echo "  provider: $provider  session: $SESSION"
  echo "  worktree: $wt"
  echo "  branch:   $branch (base $(git -C "$repo" rev-parse --short "$base_sha"))"
  echo "review with: peon report $slug"
}
```


Helpers:

```bash
meta_get() {
  python3 -c 'import json,sys; print(json.load(open(sys.argv[1])).get(sys.argv[2],""))' "$1/.peon.json" "$2"
}

find_wt() {
  local want="$1" found="" d
  for d in "$WT_ROOT"/*/; do
    [ -f "$d/.peon.json" ] || continue
    if [ "$(meta_get "$d" slug)" = "$want" ]; then
      [ -z "$found" ] || die "ambiguous slug '$want' (multiple worktrees match)"
      found="${d%/}"
    fi
  done
  [ -n "$found" ] || die "no peon found with slug: $want (see 'peon list')"
  printf '%s\n' "$found"
}

cmd_list() {
  local filter=""
  while [ $# -gt 0 ]; do
    case "$1" in
      --repo) filter="$(resolve_repo "${2:-}")"; shift 2 ;;
      *) die "unknown list option: $1" ;;
    esac
  done
  local d slug provider branch repo report
  printf '%-22s %-7s %-28s %-8s %s\n' "SLUG" "PROV" "BRANCH" "REPORT" "REPO"
  for d in "$WT_ROOT"/*/; do
    [ -f "$d/.peon.json" ] || continue
    repo="$(meta_get "$d" repo)"
    [ -z "$filter" ] || [ "$repo" = "$filter" ] || continue
    slug="$(meta_get "$d" slug)"; provider="$(meta_get "$d" provider)"; branch="$(meta_get "$d" branch)"
    report="no"; [ -f "$d/PEON_REPORT.md" ] && report="yes"
    printf '%-22s %-7s %-28s %-8s %s\n' "$slug" "$provider" "$branch" "$report" "$repo"
  done
}

cmd_report() {
  local wt base_sha
  wt="$(find_wt "${1:-}")"
  base_sha="$(meta_get "$wt" base_sha)"
  echo "== peon: $(meta_get "$wt" slug) ($(meta_get "$wt" provider)) =="
  echo "task: $(meta_get "$wt" task)"
  echo
  if [ -f "$wt/PEON_REPORT.md" ]; then
    cat "$wt/PEON_REPORT.md"
  else
    echo "(no PEON_REPORT.md yet — peon may have failed or still be running)"
  fi
  echo
  echo "== commits =="
  git -C "$wt" log --oneline "$base_sha..HEAD"
  echo
  echo "== diffstat vs base =="
  git -C "$wt" diff --stat "$base_sha" HEAD
}

cmd_diff() {
  local wt
  wt="$(find_wt "${1:-}")"
  git -C "$wt" diff "$(meta_get "$wt" base_sha)" HEAD
}
```

Wire the `case`: `list) cmd_list "$@" ;;`, `report) cmd_report "$@" ;;`, `diff) cmd_diff "$@" ;;`

```bash
poke_prompt() {
  cat <<EOF
Revision request from your reviewer on the work you already did in this worktree:

$feedback

Apply the requested changes and commit them to the current branch. Update PEON_REPORT.md to reflect the revision and commit that too. Same rules as before: never touch .peon.json, do not push, do not switch branches.
EOF
}

run_fake_resume() {
  local wt="$1" pf="$2"
  ( cd "$wt" \
    && cat "$pf" >> "FAKE_WORK-$slug.txt" \
    && git add "FAKE_WORK-$slug.txt" && git commit -qm "fake: apply feedback" \
    && printf '\nrevised per feedback.\n' >> PEON_REPORT.md \
    && git add PEON_REPORT.md && git commit -qm "fake: update report" )
}

cmd_poke() {
  local slug="${1:-}" feedback="${2:-}"
  [ -n "$slug" ] || die "usage: peon poke <slug> \"<feedback>\""
  [ -n "$feedback" ] || die "no feedback given"
  local wt provider session pf
  wt="$(find_wt "$slug")"
  provider="$(meta_get "$wt" provider)"
  session="$(meta_get "$wt" session)"
  [ -n "$session" ] || die "no session recorded for $slug (dispatch may have failed) — 'peon scrap $slug' and re-dispatch"
  pf="$LOG_ROOT/$slug.poke.md"
  mkdir -p "$LOG_ROOT"
  poke_prompt > "$pf"
  case "$provider" in
    fake)  run_fake_resume "$wt" "$pf" ;;
    codex) die "codex resume not implemented yet" ;;
    grok)  die "grok resume not implemented yet" ;;
    *) die "unknown provider in metadata: $provider" ;;
  esac
  echo "poked $slug — review with: peon report $slug"
}
```

```bash
cleanup_peon() {
  local repo="$1" wt="$2" slug="$3" delflag="$4"
  git -C "$repo" worktree remove --force "$wt" 2>/dev/null || { rm -rf "$wt"; git -C "$repo" worktree prune; }
  git -C "$repo" branch "$delflag" "peon/$slug" 2>/dev/null || true
  rm -f "$LOG_ROOT/$slug".*
}

cmd_merge() {
  local slug="${1:-}" into=""
  [ -n "$slug" ] || die "usage: peon merge <slug> [--into REF]"
  shift || true
  while [ $# -gt 0 ]; do
    case "$1" in
      --into) into="${2:-}"; shift 2 ;;
      *) die "unknown merge option: $1" ;;
    esac
  done
  local wt repo branch task current f
  wt="$(find_wt "$slug")"
  repo="$(meta_get "$wt" repo)"
  branch="$(meta_get "$wt" branch)"
  task="$(meta_get "$wt" task)"
  require_clean "$repo" "merge target $repo"
  if [ -n "$into" ]; then
    current="$(git -C "$repo" symbolic-ref --short HEAD 2>/dev/null || echo DETACHED)"
    [ "$current" = "$into" ] || die "--into $into but $current is checked out — check out $into yourself first (peon never switches your branch)"
  fi
  if ! git -C "$repo" merge --no-ff --no-commit "$branch" >/dev/null 2>&1; then
    git -C "$repo" merge --abort 2>/dev/null || true
    die "merge of $branch does not apply cleanly — resolve manually or 'peon poke $slug' to have it rebase/fix"
  fi
  for f in PEON_REPORT.md .peon.json; do
    if git -C "$repo" cat-file -e "$branch:$f" 2>/dev/null; then
      git -C "$repo" rm -qf "$f" 2>/dev/null || true
    fi
  done
  git -C "$repo" commit -qm "merge peon/$slug: $(printf '%.60s' "$task")"
  cleanup_peon "$repo" "$wt" "$slug" -d
  echo "merged $branch into $(git -C "$repo" symbolic-ref --short HEAD 2>/dev/null || echo HEAD) and cleaned up"
}

cmd_scrap() {
  local slug="${1:-}"
  [ -n "$slug" ] || die "usage: peon scrap <slug>"
  local wt repo
  wt="$(find_wt "$slug")"
  repo="$(meta_get "$wt" repo)"
  cleanup_peon "$repo" "$wt" "$slug" -D
  echo "scrapped $slug (worktree and branch removed, work discarded)"
}
```

```bash
dry_run_stub() {  # $1=wt, rest=cmdline — record the command; fake a commit so lifecycle continues.
  local wt="$1"; shift
  printf '%s\n' "$*" >> "$LOG_ROOT/$slug.cmd"   # $slug via dynamic scope from cmd_dispatch/cmd_poke
  ( cd "$wt" && echo "dry" >> DRY_RUN.txt && git add DRY_RUN.txt && git commit -qm "dry-run" )
  SESSION="dry-run"
}

run_codex() {
  local wt="$1" pf="$2" log="$LOG_ROOT/$slug.codex.jsonl"
  if [ "${PEON_DRY_RUN:-0}" = "1" ]; then
    dry_run_stub "$wt" "codex exec --json -s workspace-write -c approval_policy=never - < $pf"
    return
  fi
  ( cd "$wt" && codex exec --json -s workspace-write -c approval_policy=never - < "$pf" ) \
    > "$log" 2>"$LOG_ROOT/$slug.codex.err" || die "codex exec failed — see $log"
  SESSION="$(sed -n 's/.*"session_id"[^"]*"\([0-9a-f-]\{36\}\)".*/\1/p' "$log" | head -1)"
  [ -n "$SESSION" ] || SESSION="$(grep -oE '[0-9a-f]{8}(-[0-9a-f]{4}){3}-[0-9a-f]{12}' "$log" | head -1)"
  [ -n "$SESSION" ] || die "could not extract codex session id from $log (poke will not work)"
}

run_codex_resume() {
  local wt="$1" pf="$2" session="$3" log="$LOG_ROOT/$slug.codex.jsonl"
  if [ "${PEON_DRY_RUN:-0}" = "1" ]; then
    dry_run_stub "$wt" "codex exec resume $session -s workspace-write -c approval_policy=never - < $pf"
    return
  fi
  ( cd "$wt" && codex exec resume "$session" -s workspace-write -c approval_policy=never - < "$pf" ) \
    >> "$log" 2>>"$LOG_ROOT/$slug.codex.err" || die "codex resume failed — see $log"
  SESSION="$session"
}

run_grok() {
  local wt="$1" pf="$2" log="$LOG_ROOT/$slug.grok.log"
  SESSION="$(uuidgen | tr 'A-Z' 'a-z')"
  if [ "${PEON_DRY_RUN:-0}" = "1" ]; then
    dry_run_stub "$wt" "grok -s $SESSION --sandbox workspace --permission-mode $GROK_PERM_MODE --prompt-file $pf"
    SESSION="dry-run"
    return
  fi
  ( cd "$wt" && grok -s "$SESSION" --sandbox workspace --permission-mode "$GROK_PERM_MODE" --prompt-file "$pf" ) \
    > "$log" 2>&1 || die "grok failed — see $log"
}

run_grok_resume() {
  local wt="$1" pf="$2" session="$3" log="$LOG_ROOT/$slug.grok.log"
  if [ "${PEON_DRY_RUN:-0}" = "1" ]; then
    dry_run_stub "$wt" "grok --resume $session --sandbox workspace --permission-mode $GROK_PERM_MODE --prompt-file $pf"
    return
  fi
  ( cd "$wt" && grok --resume "$session" --sandbox workspace --permission-mode "$GROK_PERM_MODE" --prompt-file "$pf" ) \
    >> "$log" 2>&1 || die "grok resume failed — see $log"
  SESSION="$session"
}
```

```markdown
# Peon Poke — Farm Implementation Work to External CLI Agents

`/plan-check` pulls **opinions** in; `/peon-poke` pushes **labor** out. An external agent (a "peon") does an implementation chore in an isolated git worktree; Claude — the foreman — reviews the work and merges it or sends it back. Nothing reaches the real working tree without review and an explicit merge.

All mechanics live in the `peon` script — never hand-roll worktrees or provider CLI calls. If `command -v peon` fails, tell the user to install it (README of ytubecoder/codex-in-claude) and stop.

## Commands

| Command | Does |
|---|---|
| `peon dispatch <codex\|grok> "<task>" [--repo DIR] [--base REF] [--slug NAME] [--force]` | Create worktree + `peon/<slug>` branch, run the provider inside it. Synchronous — background it (`run_in_background`) to keep working. |
| `peon list [--repo DIR]` | Active peons and whether their report is in |
| `peon report <slug>` | PEON_REPORT.md + commits + diffstat vs base |
| `peon diff <slug>` | Full diff vs base |
| `peon poke <slug> "<feedback>"` | Resume the same provider session for revisions |
| `peon merge <slug> [--into REF]` | After review: merge, strip the report, clean up |
| `peon scrap <slug>` | Discard the work, remove worktree + branch |

## Workflow

1. **Scope the task.** Peons execute; they don't design. Good: a feature slice, a refactor, tests, docs — one well-defined chore with clear done-criteria. If the task is ambiguous, tighten it (or brainstorm with the user) before dispatch. Include acceptance criteria and relevant file paths in the task text.
2. **Dispatch.** One peon per task. Parallel peons = *different* tasks (never the same task to two providers — that's plan-check's council, not labor). Provider: user's choice if stated, else either. Dirty repo? Ask the user before `--force` — dispatch branches from the last *commit*, so uncommitted work is invisible to the peon.
3. **Wait.** Dispatch is synchronous (minutes). Background it and continue other work, or wait if idle.
4. **Review like a code review.** `peon report <slug>`, then `peon diff <slug>`. Judge correctness, conventions, tests, scope-creep against your conversation context — you know things the peon does not. Then either `peon poke <slug> "<specific feedback>"` (repeatable) or `peon merge <slug>`.
5. **Report to the user.** Summarize what the peon did, your review verdict, and what you merged or why you poked/scrapped.

## Rules

- **Never merge without reviewing the diff.** Draft-until-reviewed is the whole point.
- **Never bypass the script** to poke provider sessions or touch `peon/*` branches by hand.
- Peons are sandboxed to their worktree and may lack network access — don't dispatch tasks needing `npm install` of new deps without checking the result carefully.
- A failed peon leaves its worktree for inspection: `peon report` still works; `peon scrap` cleans up.
- Merge conflicts are the foreman's job: resolve manually or `peon poke` the peon to rebase onto an updated base.
```
